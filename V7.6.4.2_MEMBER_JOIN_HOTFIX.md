# v7.6.4.2 Member Join Hotfix

## Actual root cause

The invited user is not yet a Trip member. However v7.6.4.1 called:

getDoc(trips/{tripId}/members/{inviteeUid})

before the join batch.

The Security Rules correctly allow members collection reads only after the UID is
already in the Trip membership, so this preflight read itself returned permission-denied.

## Fix

- Do not read the invitee member document before joining.
- Read the parent Trip document and inspect memberUids instead.
- If the UID is not present, run the pending-invite-authorized atomic join.
- If the UID is already present, only then read the member doc as an idempotent retry.
- Friendly permission error now references v7.6.4.2 instead of the stale v7.6.4 label.

## Rules

The membership Rules from v7.6.4.1 are retained. If v7.6.4.1 rules are already
published, there is no logical rules change required by this specific hotfix.
The bundled firestore.rules is still included for consistency.
