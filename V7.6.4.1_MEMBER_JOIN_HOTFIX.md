# v7.6.4.1 Member Join Hotfix

## Root cause addressed
v7.6.4 self-join rules coupled three projected writes too tightly:
- new member doc
- parent Trip memberUids/memberCount
- invitation pending -> accepted

The self-join authorization now uses the still-valid pending invitation (email + role + trip)
and the projected member/Trip state. The invitation document's own update rule separately
validates the pending -> accepted transition.

## Additional fixes
- Join writes memberUids/memberCount as exact values rather than relying on increment().
  This also repairs older Trip documents if memberCount was stale.
- Membership batch commit is now the user-visible success boundary.
- Activity Log is best-effort after a successful join. A logging failure no longer causes
  the App to falsely report that joining the Trip failed.
- Existing-member retry is idempotent.

## Required
Republish Firestore Rules:

firebase deploy --only firestore:rules

No index change is required.
