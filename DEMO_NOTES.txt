Travel Webapp Phase 2B v7.3.0 Multi Trip Schema

Purpose
Phase 2B establishes the clean multi trip data model before Firebase import and cloud loading are enabled.

Implemented
1. Portable trip schema upgraded to schemaVersion 2 with tripId and revision.
2. Every day has a stable dayId and sortOrder.
3. Every itinerary item has a stable itemId, sortOrder and normalized image metadata while the legacy gallery array remains compatible with the current renderer.
4. Saved places have stable placeId values.
5. Added trip-schema-service.js to validate portable JSON and build the future Firestore write plan.
6. Firestore plan separates trip metadata, members, days, items, savedPlaces, general settings and expense settings instead of using one oversized document.
7. Added trip-catalog-service.js for the future same URL multi trip library using trips.memberUids.
8. The 旅程 tab is now a multi trip library shell. The current bundled JSON remains the active trip during Phase 2B.
9. Signed in users without a member document are no longer treated as Viewer. Viewer is now an explicit assigned role.
10. Expense module no longer shows a permission alert merely because the new Firestore project is empty. Until a trip is imported and a member role exists, expense cloud writes remain read only.

Multi trip discovery
The trip root document contains memberUids. After Security Rules are installed, the app can query trips where memberUids contains the signed in uid and render all accessible trips in one app. The canonical role remains the member document.
