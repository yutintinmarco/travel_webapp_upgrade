v7.4.2 — Phase 2C Final Refinement

BASELINE
• Built from v7.4.1, which itself is based directly on user-approved v7.3.13.
• The v7.3.13 Claude navigation compositor fix is untouched.

SAME-JSON / CHANGE DETECTION
• Existing trip imports are compared against current Firestore content before any snapshot or write.
• If the uploaded JSON is unchanged, the app shows 「沒有變更」 and performs no snapshot, no revision increment and no itinerary write.
• Real changes show a preview summary for itinerary items, days, saved places, trip metadata and settings.
• Only real changes proceed to pre-import Snapshot + Replace.
• importTrip has a second server-state guard, so a stale UI cannot accidentally create a no-op snapshot.
• A deterministic content fingerprint is stored after the next real Create/Replace so later same-content checks can be fast. Legacy v7.4.1 trips without a fingerprint fall back to a full structural comparison.

PHASE 2C IMPORT
• 我的 → 我的旅程 → 匯入 trip.json remains live.
• JSON is parsed locally first, normalized to schema v2, validated, and previewed before any Firestore write.
• New trip: current signed-in Google user becomes Owner automatically.
• Existing trip: only Owner/Admin can replace it.
• Replace import creates a pre-import snapshot first, preserves members, expense records and previous snapshots, then updates itinerary/settings.
• Import failures remain isolated from the local trip.json renderer.

MAPS-READY SCHEMA
• Every itinerary item and saved place keeps the normalized location object prepared for Phase 3 Google Maps / Routes / Transit.
• No coordinates or Place IDs are guessed.

ARCHIVE WRITER
• Owner/Admin can archive non-current cloud trips and restore archived trips.
• Archive keeps the trip in Firebase; only archived metadata changes.

FIRESTORE SETUP
• Existing Phase 2C firestore.rules and firestore.indexes.json remain valid; no Rules republish is required solely for v7.4.2 if v7.4.1 rules are already published.
• Phase 2F remains the final security hardening and rule regression phase.
