v7.5.0 — Phase 2D Backup & Recovery

Baseline
• Built directly from the stable v7.4.3 Phase 2C build.
• The v7.3.13 profile navigation compositor is unchanged.

Phase 2D
• Firebase → portable trip.json export.
• Snapshot history in 我的 → 旅程設定 → 行程匯出與備份.
• Manual Snapshot creation for Owner / Admin.
• Snapshot detail page with export and restore.
• Restore automatically creates a pre-restore safety Snapshot.
• Restore preserves memberUids, memberCount, creator, archive state, members subcollection and expenses subcollection.
• Restore increments revision and writes an activity log.
• Snapshot history is capped to the latest 10 entries in the UI.

Phase boundary
• The itinerary UI still renders from local trip.json until Phase 2E. Firebase restore is therefore visible in Firestore/export immediately, but not yet used to redraw the main itinerary.

Firebase
• Existing Phase 2C Firestore Rules are sufficient.
• No new composite index is required for Phase 2D.

Phase 2E v7.6.2
Firebase Loader is now the live data source after authenticated Trip catalog resolution.
Bundled trip.json remains the immediate bootstrap and signed-out fallback.
Quick Trip Switcher and My Trips now switch live Firebase Trips.
Persistent Firestore local cache is enabled when supported.

v7.6.2 Phase 2E UX refinement
- Restore and JSON import now use a blocking Liquid Glass progress overlay with percentage and stage detail.
- Operation Records moved from Expense Management to My > Trip Settings and now represents trip-wide audit history.
- Existing legacy activity documents are rendered with meaningful action titles; new writers store structured action metadata.
- v7.3.13 navigation transition block remains byte-for-byte unchanged from v7.6.0.
